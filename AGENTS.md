# MEAMO — постоянные инструкции для Codex

## Цель

Сверстать 11 адаптивных страниц B2B-сайта MEAMO в **имеющемся статическом проекте**. Приоритеты: соответствие макетам, минимальное количество кода, понятные БЭМ-блоки, переиспользуемые SCSS-стили и JavaScript. Впоследствии HTML будет перенесён в MODX; **сейчас MODX не подключать**. Нет корзины, цен, онлайн-оплаты и модальных окон для заявок.

## Жёсткие ограничения: никаких новых инструментов и инфраструктуры

Исходная база — `index.html`, `scripts/main.js`, `styles/` (включая `styles/blocks/` и `styles/css/styles.css`), `fonts/`, `images/`. Продолжай **непосредственно в этих файлах**.

**Разрешено добавлять только:**
- отдельные HTML-страницы в корне, **по мере их реализации**, а не пустые файлы для всех страниц сразу;
- SCSS-файлы в существующем `styles/blocks/` для действительно новых самостоятельных компонентов;
- необходимые правила в существующих SCSS и код в `scripts/main.js`;
- записи о результате в `docs/PROGRESS.md`.

**Запрещено без отдельного прямого разрешения пользователя:**
- создавать `package.json`, `package-lock.json`, `.npmrc`, `node_modules/`; устанавливать npm-зависимости;
- подключать Nunjucks, Vite, Webpack, Gulp, шаблонизаторы, фреймворки, сборщики HTML или генераторы страниц;
- создавать `templates/`, `data/`, `qa/`, `tools/`, `tests/`, `build/`, `dist/` и другие вспомогательные каталоги;
- добавлять файлы настроек сборки, проверки, браузерных тестов, маршрутизации, JSON с содержимым страниц, дополнительные JS-модули, скрипты запуска;
- менять `README.md`, `AGENTS.md`, `docs/PAGE_MAP.md`, `docs/PROMPTS.md`, конфигурацию Git/Vercel, если текущий этап не содержит отдельного прямого запроса;
- делать коммиты, массовый рефакторинг, переписывать стек или заранее реализовывать будущие страницы.

**Важное различие:** разрешено *проверять* результат внешними доступными инструментами, но не создавать ради проверки инфраструктуру или постоянные артефакты в репозитории. Если `sass` уже доступен как команда, компилируй существующий `styles/styles.scss` непосредственно в `styles/css/styles.css` (без npm). Если команды нет — сообщи, не устанавливай зависимости и не создавай сборку самостоятельно. Локальный просмотр можно выполнить существующим способом (например, редактором/простым внешним сервером), не добавляя проектные скрипты.

## Как переиспользовать без шаблонизатора

- **Один смысловой БЭМ-блок — одни SCSS-стили**. Для разновидностей применять `__element` и `--modifier`, а не создавать копии компонентов.
- **Один обработчик поведения** в `scripts/main.js` для однотипных элементов на разных страницах. Код должен нормально работать, если элемента нет на текущей странице.
- Разметка общих Header/Footer **может повторяться в независимых HTML-файлах**. Это осознанное допустимое дублирование для статического прототипа; позднее оно заменится MODX-чанками. **Не создавать ради удаления этого дублирования шаблонизатор, JS-вставку общих HTML-блоков или систему компонентов**.
- БЭМ `block`, `block__element`, `block--modifier`; SCSS рядом с уже существующими блоками. Информационная `card` может иметь варианты `--icon`, `--text`, `--white`, `--icon-side`, `--enum`; товар, категория, документ и статья могут быть отдельными семантическими карточками. Не создавать класс/файл ради каждого заголовка секции.
- Не писать абстракции, конфигурации, универсальные функции, комментарии, состояния и защитные оболочки «на будущее». Достаточно кода для **текущей** страницы и согласованной интерактивности.

## Источники и схема страниц

- `docs/PAGE_MAP.md` — **готовая карта** всех страниц: номера и порядок логических узлов, элементы, модификаторы, переиспользование. Не анализировать структуру заново с нуля.
- `files/Страницы/` — точные компьютерные (1440) и мобильные (375) макеты; `files/Состояния/` — варианты состояний; `files/UI Kit/` — визуальная система.
- `files/MEAMO_ТЗ_верстальщику.docx` — дополнения и правила приёмки; `files/MEAMO_ТЗ_программисту_MODX.docx` — справка о будущей интеграции, не текущая задача.
- `docs/PROGRESS.md` — только факты выполненного, важные решения и ограничения.

Реализуй **ровно логические узлы текущего этапа** из `PAGE_MAP.md`, не открывай новый проект и не перестраивай его. Используй исходные изображения; условные числа, `[TEMP]`, неподтверждённые документы, отзывы, адреса и контакты не выдавать за реальные сведения. Файла `MEAMO_Открытые_вопросы.md` не будет — не искать и не создавать.

## SCSS и адаптивность

- Пользоваться существующими переменными, миксинами и шрифтами Bitter/GolosText. Исправлять обнаруженные ошибки (например, `line-height: 1.55px` и текущую формулу `fluid-text`) **точечно**, не переписывая все стили.
- Главный адаптивный миксин — `@include mobile`. `desktop`, `tablet`, `mobile-s` — лишь при реальной необходимости; предпочитать Grid/Flex, `minmax()`, `clamp()`, естественный перенос.
- Если размер шрифта отличается на ПК и телефоне, **только `@include fluid-text(max, min)`**. Для этой задачи нельзя задавать другой `font-size` внутри `mobile`. Сигнатуру миксина сохранить; интерполяцию между 375 и 1440 px исправить при необходимости.
- Контейнер: при 1440 — 1280 px + поля 80 px, при 375 — 327 px + поля 24 px; другие размеры по устойчивости макета. Не фиксировать высоту блока, если её задаёт контент. Товарные изображения — полностью видимые (`object-fit: contain`). Не скрывать ошибку переполнения глобальным `overflow-x: hidden`.
- Разметка семантическая: H1, заголовки, `a` для ссылок, `button` для действий, подписи к полям, `:focus-visible`, корректные состояния клавиатуры. Без лишних анимаций.

## Поведение без вымышленного backend

- Header: непрозрачный закреплённый, доступное мобильное меню; поиск только по товарам/брендам. Основной слайдер — стрелки, номера, мобильный свайп, **без автопрокрутки**. Hero Labs статичен.
- Каталог: боковые фильтры и отдельная мобильная панель; Grid/List — два вида одной выдачи; сортировка по умолчанию / названию А–Я / Я–А; цифровая пагинация. Значения фильтра: «ИЛИ» внутри группы, «И» между группами. **Не строить собственный API, маршрутизатор, URL-синхронизацию, тестовый источник данных или универсальный менеджер состояния ради имитации серверного каталога.** Реализовать интерфейс и доступное локальное поведение, которое возможно на статической странице; серверную зависимость зафиксировать.
- На товаре «Характеристики», «Описание», «Материалы» — якорные секции, не табы со скрытым текстом. Документы конкретного товара не путать с документами линейки.
- Формы: `compact-request` и `wholesale-request` с общим оформлением полей. **Никаких модалок**. «Запросить условия» — к местной форме либо на предусмотренную страницу; «Запросить документы» — к форме с контекстом товара/материала. Успех вместо формы **только после подтверждения сервером**. При ошибке сохранять ввод. Пока обработчика нет — честно оставлять отправку неподключённой; **не писать фиктивный API или большую архитектуру отправки**.
- Не добавлять неподтверждённые `required`, ограничения вложений, sticky-элементы и бизнес-правила. Мобильный выезжающий блок допускается для фильтров, не для форм.
